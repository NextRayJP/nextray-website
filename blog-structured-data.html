構造化データ（JSON-LD）とは｜検索エンジンとAIへの「自己紹介文」

構造化データとは何か

構造化データとは、ページの内容を、機械が誤解なく読める形式で書き添えたものです。画面には表示されず、HTMLの中に埋め込まれます。

書き方はいくつかありますが、現在Googleが推奨している方式がJSON-LD（ジェイソン・エルディー）です。「項目名: 値」の組み合わせを並べるだけの、住所録のような単純な形式です。たとえば「name: NextRay」「telephone: 080-7517-4514」のように書きます。

項目名は自己流ではなく、schema.org（スキーマ・ドット・オルグ）という共通の語彙集から選びます。GoogleやMicrosoftなどが共同で策定したもので、世界中のサイトが同じ語彙を使うことで、機械が迷わず読めるようになっています。

なぜ「自己紹介文」が要るのか

人間は、ページを見れば「これは会社案内だな」「この数字は電話番号だな」と文脈で分かります。しかし機械にとって、HTMLの中の「080-7517-4514」という文字列が電話番号なのか、商品番号なのかは、推測するしかありません。

構造化データは、この推測をなくします。「これは電話番号です」「これは記事の公開日です」とラベル付きで明記するので、検索エンジンは安心してその情報を使えます。

そしてもうひとつ、読み手が増えました。AIです。ChatGPTやGeminiに「新潟のホームページ制作会社を教えて」と尋ねる人が増えており、AIがページを読んで答えを組み立てる場面では、内容が明記されているページの方が誤読されにくいはずです。当社がllms.txtというAI向けの案内ファイルと併せて構造化データを整備しているのは、この流れを見てのことです。

実物① 事業者情報——「NextRayは何者か」

ここからは、当社サイトに実際に入っているコードを抜粋して見ていきます。まずトップページに入れている事業者情報です。

nextray.jp トップページのJSON-LD（抜粋・整形） 
{
  "@context": "https://schema.org",
  "@type": "ProfessionalService",
  "name": "NextRay",
  "alternateName": "ネクストレイ",
  "url": "https://nextray.jp/",
  "founder": {
    "@type": "Person",
    "name": "谷川恵介",
    "jobTitle": "代表"
  },
  "numberOfEmployees": { "@type": "QuantitativeValue", "value": 1 }
}

「@type」がこのデータの種類です。ProfessionalServiceは事業者情報（Organization）の一種で、専門サービス業を表します。読み方はそのままで、「NextRayという専門サービス業者で、読み仮名はネクストレイ、代表は谷川恵介、人数は1名」と機械の言葉で自己紹介しています。

実物にはこのほか、所在地、電話番号、営業エリア、サービス内容、保有資格まで書いています。ポイントは「従業員1名」まで正直に書いていることです。構造化データは機械への申告なので、実態と違うことを書く場所ではありません。

実物② 記事情報——「誰がいつ書いたか」

コラムの各記事には、BlogPosting（ブログ記事）というデータを入れています。いまお読みのこのページにも入っています。

この記事のJSON-LD（抜粋・整形） 
{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "構造化データ（JSON-LD）とは",
  "datePublished": "2026-08-08",
  "author": { "@type": "Person", "name": "谷川恵介" },
  "publisher": { "@type": "Organization", "name": "NextRay" }
}

見出し、公開日、書いた人、発行元を明記しています。検索エンジンが「いつの情報か」「誰が書いたか」を判定する材料になります。情報の鮮度と書き手が分かる記事として扱ってもらうための申告です。

実物③ FAQ——「よくある質問と答え」

記事の中に「よくあるご質問」の節がある場合、その質問と答えをFAQPageというデータでも書いています。

この記事のFAQPage（抜粋・整形） 
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    { "@type": "Question",
      "name": "構造化データを入れると検索順位は上がりますか？",
      "acceptedAnswer": { "@type": "Answer",
        "text": "順位が直接上がるとは言えません。……" } }
  ]
}

注意点がひとつあります。本文に書いていない質問と答えを、構造化データにだけ書いてはいけません。Googleのガイドラインでも、ページに表示されている内容と一致させることが求められています。当社は、本文のFAQ節とJSON-LDのFAQを必ず同じ内容にしています。

実物④ パンくずリスト——「サイト内の現在地」

4つ目はBreadcrumbList（パンくずリスト）です。ページ上部の「ホーム ／ コラム ／ 記事名」という表示の、機械向けの写しです。

この記事のBreadcrumbList（抜粋・整形） 
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "ホーム" },
    { "@type": "ListItem", "position": 2, "name": "コラム" },
    { "@type": "ListItem", "position": 3, "name": "この記事" }
  ]
}

このページがサイトのどの位置にあるかを伝えます。検索結果でURLの代わりに「nextray.jp › コラム」のような階層表示が使われることがあり、その材料になります。

リッチリザルトは保証されない

構造化データの話には、よく「リッチリザルト」という言葉がついてきます。検索結果に星やFAQや階層表示が付く、通常より情報の多い表示のことです。

ここで正直に書いておきます。構造化データを正しく入れても、リッチリザルトが表示されるとは限りません。Google自身が、表示するかどうかは検索エンジン側の判断だと明言しています。実際、表示の仕様は年々変わっており、以前はよく見かけたFAQの展開表示も、現在はほとんどのサイトで出なくなりました。

ですから当社は、リッチリザルトを目的に構造化データを入れているのではありません。目的は、検索エンジンとAIに内容を正確に伝えることです。見た目の恩恵はあれば幸運、というくらいの位置づけが実態に合っていると思います。「構造化データで検索結果が豪華になります」という売り文句だけを聞いたら、この保証されない性質もセットで確認することをおすすめします。

同じ理由で、構造化データを入れれば検索順位が上がる、とも言えません。順位を決めるのはあくまで内容です。当社は順位の保証をしていませんし、この記事もその立場で書いています。

自分のサイトを確認する方法

自社サイトに構造化データが入っているかは、無料で確認できます。

  • 検索で「リッチリザルトテスト」と調べ、Googleの公式ツールを開く
  • 自社サイトのURLを入力してテストする
  • 検出された構造化データの種類と、エラーの有無が表示される
  • 「検出されませんでした」なら、そのページに構造化データは入っていない

制作会社に依頼しているサイトなら、これで「見えない部分の仕事」がひとつ確認できます。入っていないから悪い、と短絡する必要はありませんが、「SEO対策込み」をうたう契約で基本的な構造化データが何も入っていないなら、何をもってSEO対策としているのかを聞いてみる価値はあると思います。

よくあるご質問

構造化データを入れると検索順位は上がりますか？

順位が直接上がるとは言えません。構造化データの主な役割は、検索エンジンやAIにページの内容を正確に理解してもらうことと、検索結果の見た目が豊かになる可能性（リッチリザルト）です。順位を保証するものではなく、当社も順位の保証はしていません。

構造化データを入れれば、必ずリッチリザルトが表示されますか？

表示されるとは限りません。Googleは、構造化データが正しく書かれていても、リッチリザルトを表示するかどうかは検索エンジン側が判断すると明言しています。正しく書くことは表示の前提条件であって、表示の約束ではありません。

構造化データはページを見ても見えないのに、なぜ入れるのですか？

読み手が人間だけではなくなったからです。検索エンジンとAIは、ページの見た目ではなくHTMLの中身を読んでいます。人間には同じに見えるページでも、機械にとっては「内容を推測するしかないページ」と「内容が明記されているページ」の差があります。構造化データはその明記の部分です。

自分のサイトに構造化データが入っているか確認できますか？

できます。Googleが無料で公開している「リッチリザルトテスト」にURLを入力すると、そのページの構造化データが検出されるか、エラーがないかを誰でも確認できます。当社にURLをお送りいただければ、こちらで確認してお伝えすることもできます。費用はかかりません。
